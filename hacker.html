CASE FILE // 005 · SOFTEL SOLUTIONS

Enterprise Hybrid RAG & GraphRAG Platform

High-scale retrieval orchestration serving 15,000+ daily queries for 1,200+ users.

Role
Python Developer (AI/ML)
Scale
15K+ QPS · 1,200+ Users
Verification
400-query test set (Ragas)
Impact
-22% Hallucinations · -35% Latency

// the challenge

Standard dense vector search suffered from context fragmentation when queries required multi-hop entity reasoning across disparate corporate documents. This resulted in factual hallucinations in 28% of complex enterprise queries and unacceptably high retrieval latency under concurrent user load.

// architecture & pipeline

User Query → Hybrid Retriever (BM25 + ChromaDB) → Neo4j Cypher Traversal → Cross-Encoder Reranker → LLM Context Stream
  • Hybrid Retrieval Fusion: Unified dense semantic search (ChromaDB cosine similarity) with sparse keyword matching (BM25) to catch specific entity IDs and domain keywords.
  • Knowledge Graph Linking: Extracted entity-relationship triples into Neo4j, enabling multi-hop graph traversals that surface hidden contextual dependencies.
  • Async Queueing & Workers: Containerized FastAPI microservices paired with Redis RQ workers to handle high-throughput query spikes without blocking the API gateway.
  • Cross-Encoder Reranking: Scored candidate contexts with a fine-tuned cross-encoder, trimming prompt tokens by 40% while preserving crucial evidence.

// evaluation & results

  • 15K+daily queries handled smoothly
  • 1,200+enterprise users served
  • -22%hallucination reduction via Ragas
  • -35%query latency drop (P95 < 140ms)

// stack

  • ChromaDB
  • Redis RQ

Talk2DB: Autonomous NL-to-Query Agent

Natural language to validated multi-database queries across SQL and NoSQL engines.

Role
AI & ML Intern
Supported DBs
PostgreSQL, MySQL, MongoDB
Reliability
100% AST Syntax Validation
Latency
< 180ms Query Synthesis

// the challenge

Operational teams needed instant business insights from production databases without writing complex SQL or MongoDB aggregations. Direct LLM-to-SQL approaches frequently produced hallucinated column names, invalid joins, and dangerous modification queries.

// architecture & pipeline

Natural Prompt → Mem0 Schema Memory → AST Syntax Validator → Read-Only Execution → Synthesized Insight
  • Dynamic Schema Memory: Integrated Mem0 to maintain an updated vector cache of table schemas, column foreign keys, and document schemas.
  • AST Validation Sandbox: Parsed every generated query into an Abstract Syntax Tree (AST), rejecting non-SELECT or destructive statements (DROP/DELETE/UPDATE) before execution.
  • Cross-Engine Compilation: Dynamic translation layer supporting both relational SQL (Postgres/MySQL) and NoSQL pipeline aggregation syntax (MongoDB).
